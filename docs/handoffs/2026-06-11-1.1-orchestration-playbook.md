# Orchestration Playbook: Milestone 1.1 (Dispatcher Reliability + Lanes)

**For:** the long-lived orchestration session that will drive 1.1 on the
operator's machine.
**Role:** *coordinator, not implementer.* You harden specs, dispatch work
to dogfooded `cw` workers and sub-agents, monitor, disposition, prune, and
file bugs. You do **not** write feature code in this context — every
implementation ticket is delegated.
**Reads:** [reconciliation + combined plan](2026-06-11-dispatcher-reliability-lanes.md)
(the what/why + ticket map), [ADR-0006](../adr/0006-reaping-is-gated-by-an-authority.md),
and RFC 0004 + ADR 0005 (land via PR #386).

## Context discipline (the whole point of this session)

Keep your context for **judgment work**; delegate everything mechanical.

| Keep in orchestrator context | Delegate out |
|---|---|
| `/harden-ticket` spec hardening before each dispatch | Implementation → `cw` dogfood workers (`/auto-dev` headless) |
| Ticket pruning / dedup / dependency sequencing | Code review of worker PRs → `/review` + review sub-agents |
| Filing bugs found mid-run | Codebase research / "where does X live" → one Haiku `Explore` sub-agent |
| Dispositioning sentinels (`/cw-followup`) | Test/lint/build runs → workers + sub-agents |
| Go/no-go on waves | Multi-file refactors → workers |

If you find yourself reading implementation files to *write* code, stop and
dispatch a ticket instead. The dogfood **is** the deliverable.

## Preconditions (before any dispatch)

   prerequisites. ADR-0006 (this branch) references those files; rebase
   `claude/milestone-1-1-queues-1g09ig` on `main` once #386 lands so all

2. **Local `cw` matches `main`** (`reconcile.py` has the #541/#544/#545

## Dispatch plan — de-risk first (operator-approved)

Reap-gating lands **early**: it depends only on the state lock (#387), and
it stops workers being reaped mid-wave — so the rest of the dogfood runs on
a dispatcher you can trust. Then the lane phases.

```
Wave 0  Foundation        #387 (state lock impl)  →  #388 sweep, #389, #391, #392, #393
Wave 1  Reap-gating       #552 (detect/act split, writes via mutate_state)
        (de-risk)           → #554 (reap_policy), #555 (REAP_PROPOSED, fixes #542)
                            → #556 (doc inversion)
Wave 2  Lanes Phase 1     #557 (lane data model, lane="default")
Wave 3  Lanes Phase 2     #558 (two-tier scheduler — the leapfrog)
Wave 4  Lanes Phase 3     #559 (lane CLI + knobs), #561 (status grouping)
Wave 5  Capstone          #560 (reap authority = lane ORCHESTRATE session)
```

Hard dependencies: `#387 → #552 → #554/#555 → #556`; `#557 → #558 → #559/#561`;
`#560` needs #554+#555 **and** RFC 0004 Phase 4 (ORCHESTRATE sessions).
Reap-gating (Wave 1) and Lanes Phase 1 (Wave 2) can overlap once #387 lands —
they touch different surfaces (`reconcile.py` act-gating vs `models.py`/
`dev_queue.py` schema). Serialize anything that co-edits `models.py`.

## Per-ticket loop (run this for each ticket)

1. **Harden** — `/harden-ticket <#>`. The reconciled ticket bodies already
   encode the RFC 0004 framing; your job is to surface implementation-
   determining ambiguities a plan-reviewer would flag and post a single
   pre-flight resolutions comment. High-value targets: #558 (scheduler
   fairness/edge cases), #554 (`reap_policy` resolution precedence),
   #559 (RFC 0004 open-question #2: auto-create vs hard-fail lane).
2. **Dispatch** — enqueue + run via `cw` (dogfood). Use `/cw-fanout` for a
   wave that respects the DAG; never fan out a ticket with its unmet
   dependency.
3. **Monitor** — `/cw-queue-peek`. Trust the `session.needs_attention` /
   `session.timed_out` bus; fall back to peek polling if the inbox wedges
   (#393 until fixed).
4. **Disposition** — `/cw-followup` on each sentinel: ship PR, draft a
   Decisions section for pending ambiguities, escalate a real blocker, or
   close a `no_op` with a citation.
5. **Quality gate** — all 7 gates per CLAUDE.md; patch coverage ≥90%
   including error paths. The worker owns this; you verify the sentinel.

## Standing responsibilities (between waves)

- **Prune** — close/merge duplicate or superseded tickets as you go. The
  reconciliation already retired the lane/state overlaps; watch for new
  dups against #366 (concurrency ceiling), #257 (wave_id), #507 (move).
- **File bugs** — anything a worker surfaces that isn't its ticket goes to a
  fresh issue, not scope-creep into the current PR (Abigail Oath).
- **Re-arm** — a wave isn't done until every ticket is terminal (MERGED /
  CLOSED / parked with a decision). Webhooks miss CI-success and
  merge-conflict transitions; re-check mergeability yourself.

  default. ✅
