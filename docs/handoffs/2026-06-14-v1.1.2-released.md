## #636 — deferred, NOT fixed (carry-forward)

`gh pr create` is blocked by the `auto` permission classifier inside the
worktree-isolated `/prep-pr` subagent in headless context (cw spawns workers
`claude --bg --permission-mode auto`; no TTY to approve). The **effective fix**
— spawn the worker with a non-`auto` `permission_mode` (needs the
bypassPermissions disclaimer accepted once interactively; the `cw doctor`
`bypass-disclaimer` advisory) — was deliberately deferred because RFC 0005's
FINALIZE/REVIEW stages (#622/#621) replace the Step 4c spawn mechanic anyway.
**Carry-forward requirement posted on #621 and #622:** the stage executor must
create the PR with permissions bypassed or it re-hits #636. Until then, a ship
that hits the block falls back to orchestrator-session PR creation (works, but
noisily — see ship-but-stuck below).

## New gotchas / lessons (carry forward — this wave was a teacher)

- **Layered ambiguity discovery is real; harden-ticket reduces it, doesn't zero
  it.** #637 took **4 auto-dev rounds**: round 1 blocked at plan review
  (MUST_FIX), round 2 passed review but raised 2 ambiguities + 1 premise, round
  3 raised 4 *new* ambiguities (event-suppression, ReconcileReport field,
  worktree cleanup, a lock-boundary contradiction in *my own* round-3 comment),
  round 4 finally implemented + shipped. Each round the PM reviewer reads the
  resolved spec against real code and finds genuinely new gaps. **For
  deep-surface tickets** (multi-function, event/report/lock semantics) expect
  2-4 harden rounds — or switch to hands-on TDD after round 2-3 rather than
  re-dispatching blind. The harden comments themselves can carry bugs (round-3
  said "`_reconcile_locked` computes outside the lock" — physically impossible;
  the reviewer caught it).
- **`dirty_worktree` is a FALSE POSITIVE from untracked `.claude/cw-context.json`.**
  It made reconcile emit `session.needs_attention(dirty_worktree)` every tick
  for stale sessions (notification spam), AND blocked re-dispatch ("stale
  worktree … has unsaved work → BLOCKED_ON_USER"). Workaround when re-dispatching
  a parked ticket: `git worktree remove --force <wt>` + `git branch -D
  auto-dev/<id>`, then `cw dev-queue remove`+`add`+`run`. **Real fix candidate:**
  the dirty-check should ignore `.claude/cw-context.json`.
- **ship-but-stuck (#578) recurred on every shipping worker.** #635/#633/#637
  each shipped a real PR that merged, but the dev-queue task stayed `running`.
  **Always validate via the real PR (`gh pr view`/`list`), never queue status.**
  After a worker ships, `cw dev-queue cancel <id>` to force the task terminal.
- **Freshness gate / auto-ff has two trip conditions.** Dispatch skips with
  `skip=freshness_gate` when (a) local `main` ref is behind origin, or (b)
  auto-ff can't run because HEAD isn't on `main` *or* the working tree is dirty.
  `is_main_behind_origin` keys on the **`main` ref vs origin**, not the
  checked-out branch — so you can clear the gate without switching branches:
  `git fetch origin main:main` (when not on main) or `git merge --ff-only
  origin/main` (when on main, survives a dirty tree if no overlap). Keeping the
  orchestrator checkout on a clean `main` is the durable fix.
- **#636 ship-block is still live.** A worker that reaches the ship stage hits
  the classifier block and falls back to orchestrator PR creation — unreliable.
  If a worker blocks at ship or ships-but-stuck, **orchestrator-open the PR from
  the pushed branch** (`gh pr create` + `--auto` squash) rather than re-dispatch.
- **Two copies of `auto-dev.md` drift.** Canonical =
  `claude-workspace/.claude/commands/auto-dev.md` (tracked, source of truth).
  Live = `~/.claude/commands/auto-dev.md` → symlink → `global-claude/commands/
  auto-dev.md` (separate repo). They diverge silently; this session global was a
  stale snapshot (missing the #578 sentinel-is-last guidance + the pre-emit `cw
  result validate` gate) **plus** the local-coder testing block. Reconciliation
  = make global equal canonical, preserving any temporary testing block. Apply
  skill/command edits to **both**.
- **Security-warning false positives** on subagent `gh issue comment` calls
  (classifier mislabels `mattwwarren` as non-org) are benign for our own repo —
  standard harden-ticket behavior.

## Release-cut recipe (re-validated this session)

Unchanged from the prior handoff and confirmed working. Branch → bump
`pyproject.toml` (only version source) → CHANGELOG `[Unreleased]`→`[x.y.z]` →
PR (CI incl. `package-smoke`) → squash-merge → `git tag -a vX.Y.Z <merged-sha>`
+ push → `release.yml` verifies `cw.__version__` == tag, builds, publishes →
`uv tool install --force --reinstall --no-cache .` → verify `cw --version` +
`cw doctor`. (This release went clean on the first tag — the v1.1.1
two-version-source failure class is gone.)
