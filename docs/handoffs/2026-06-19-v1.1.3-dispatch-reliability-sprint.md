## Execution recipe (run on the laptop, where `cw` lives)

Condensed from `2026-06-13-phase4-complete.md` — re-read its full version.

1. **Orient.** `git fetch && git reset --hard origin/main`; reinstall cw with
   **`uv tool install --force --reinstall --no-cache <repo>`** (the cache trap —
   see Gotchas); `cw dev-queue status` (expect empty); `cw doctor` (expect
   healthy). Confirm `git branch --show-current` is `main` before reading ranges.
2. **Harden each ticket:** `/harden-ticket <id>` → resolve technical ambiguities
   yourself, escalate only genuine product/arch forks (one batched question with
   a recommendation) → post the binding **Pre-flight Resolutions** comment.
3. **Dispatch:** `cw dev-queue add <id> -c claude-workspace -s small` →
   `cw dev-queue run --once` (drop `--once` to loop). For Wave 1, batch 2–3.
4. **Monitor:** event-driven Monitor on `~/.local/share/cw/dev_queue.json` —
   watch status transitions + >25-min transcript silence; terminal-filtered.
   Beats timed polling. (Skills: `cw-session-watch`, `cw-queue-peek`.)
5. **On terminal:** read the worker's **own** sentinel (role-filter assistant/
   `tool_result`, never the prompt's `pr=42` example) + verify the real PR. Then
   resolve the task to terminal **immediately** (see the stale-state Gotcha) and
   validate the gate.
6. **Salvage** if a worker dies post-impl (rate limit / #578): branch is usually
   pushed — verify the gate in a clean worktree
   (`git worktree add /tmp/verify origin/dev/<n>`) → `gh pr create` +
   `gh pr merge --squash --auto`. Pure local compute; no Claude quota.
7. **Cut v1.1.3** once the wave lands: follow the release recipe in
   `2026-06-13-sprint0-released.md` (bump `pyproject.toml` **only** — single
   version source via `importlib.metadata` now; fill CHANGELOG; PR → CI incl.
   `package-smoke`; tag at merged SHA; reinstall + `cw doctor`).

## Operator-state caveats & gotchas (load-bearing — carry forward)

- **`reap_policy: auto`** is set for claude-workspace in
  `~/.claude-workspace/orchestrator.yaml` (`per_client_max_parallel: 3`).
  Under `auto`, reconcile self-heals phantom RUNNING — but it also **re-dispatched
  a shipped ticket** last sprint (the #637 hazard, now fixed). After each worker
  finishes, force its task terminal: `cw dev-queue cancel <ticket> -c
  claude-workspace` (note: `cw done <session>` does NOT update the dev-queue
  task). Drop the cap to 2 for same-file waves.
- **uv reinstall cache trap:** `uv tool install --force` serves a STALE cached
  build when `pyproject.toml`'s version string is unchanged. `cw --version`/
  `doctor` compare the string, not the build, so they report green. Use
  `--reinstall --no-cache` and verify the new subcommand's `--help`.
- **#591 sentinel example trap** (this sprint *fixes* it, but mind it while
  operating): the `/auto-dev` prompt embeds an illustrative `pr=42` sentinel —
  any monitor/parser reading raw transcript text latches it as `shipped`. Always
  role-filter to the worker's own assistant/`tool_result` output.
- **#578 ship-but-stuck:** a worker can ship the PR + emit a real `shipped`
  sentinel, then its turn never completes → task stuck `running`. Detect via
  25-min silence + role-filtered sentinel + a real PR; salvage/clean up.
- **Stale-state root:** `reconcile()` only runs on `cw start/resume`, each
  `dispatch_tick`, `cw doctor`, `cw status/list`. No background ticker → state is
  stale for the whole gap between commands. Resolve finished tasks to terminal
  immediately (above). The #639 reconcile-cadence ADR landed but no primary
  runner exists yet.
- **Patch-coverage gate (≥90% new lines) bites new `except` branches** — cover
  every new branch, including error paths (extract import-time code to a testable
  function).
- **Worktree debt:** ~55 squash-merged-stale worktrees invisible to
  `git branch --merged` (#630). Don't mass-`git worktree remove` until a
  PR-state-based `cw worktree gc` exists; remove individually for confirmed
  merged branches.
