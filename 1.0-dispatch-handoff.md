## What 1.0 is

The SemVer 1.0 release (**tracking issue #120**) is the architectural cutover:
retire the cmux/tmux multiplexer + IDLE wrapper + reconcile-driven supervisor in
favor of Claude Code's **native supervisor + Agent SDK orchestrator**
(~3,500 LoC removed, `sessions.json` v3→v4, `claude` ≥ 2.1.139 minimum).

**Release gate (per #120):** all Phase 0–6 precursors (#105–#119) **and** #103
closed, **plus ≥2 weeks of green nightly** on the native backend, then the
release ceremony in #120.

Precursors #103, #105–#115 and multiplexer-removal Phases A–D (#165–#168) are
**already closed**. The set below is what remains open and in scope.

## Recommended dispatch sequence (dogfood `cw`)

Verified command surface (cw 0.13.0):

```bash
# Ticket IDs are issue numbers; client auto-resolves via orchestrator config
# (override with -c <client>). Confirm mapping first:
cw dev-queue status

# Step 1 — fix the pipeline-poisoning bug FIRST, on its own, and let it merge:
cw dev-queue add 381 -p 10
cw dev-queue run --once        # or use the /cw-smoke-test skill for a single-ticket
                                # validated run with a PASS/FAIL rollup

# Step 2 — after #381 is merged, fan out the rest of Tier A in parallel:
cw dev-queue add 201 263 143 -p 5
cw dev-queue run               # continuous dispatch loop; monitor the wave

# Scope guards to put in the worker prompts / ticket bodies before dispatch:
#   #263 → "Bug A only. Do NOT touch Bug B (architectural; separate brainstorm)."
#   #143 → "Verify against acceptance first; close as no_op if already satisfied."
```

**Prefer the skills over hand-rolling:**
- **`/cw-fanout`** — enqueue the Tier-A batch, start the dispatch loop, and monitor
  the whole wave (queue-peek ladder + `session.needs_attention` / `session.timed_out`
  event bus) until every ticket is terminal. This is the one-motion path for Step 2.
- **`/cw-smoke-test`** — single-ticket end-to-end validation; good for #381 in Step 1.
- **`/cw-validate-result`** / **`/cw-validate-wave`** — validate the AUTO_DEV_RESULT
  sentinels after the wave; confirm each shipped/no_op/blocked disposition.
- **`/cw-followup`** — disposition each finished run (close no_op with citation,
  open PR for merge-gate-blocked, draft Decisions for ambiguities, escalate blockers).
